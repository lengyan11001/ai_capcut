# 上线检查清单与灰度回滚预案

## 1. 上线前检查
- 配置检查
  - [ ] `novel.jwt.secret` 已替换为生产密钥
  - [ ] `novel.payment.callback-secret` 已替换并仅后端可见
  - [ ] 数据库连接、Redis 连接、时区配置正确
- 能力检查
  - [ ] 登录、书城、搜索、书架、阅读器全流程通过
  - [ ] 充值下单、回调、到账、流水查询通过
  - [ ] 管理后台运营位读取正常
- 安全检查
  - [ ] 限流生效（429 返回正常）
  - [ ] 支付回调验签失败会拒绝
  - [ ] 敏感日志脱敏（手机号、token）
- 观测检查
  - [ ] 健康检查可用：`/actuator/health`、`/healthz`
  - [ ] 指标可抓取：`/actuator/prometheus`
  - [ ] 错误告警链路可触发

## 2. 灰度发布策略
- 阶段 1（1% 用户）：
  - 仅内部员工 + 白名单用户。
  - 观察 2-4 小时：错误率、支付成功率、章节耗时。
- 阶段 2（10% 用户）：
  - 开放自然流量 10%，持续观察 1 天。
- 阶段 3（50% 用户）：
  - 扩量并重点关注支付与阅读留存指标。
- 阶段 4（100%）：
  - 指标稳定后全量。

## 3. 回滚预案
- 应用回滚
  1. 切流到上一个稳定版本。
  2. 回滚镜像 tag 并重启实例。
  3. 核验健康检查与关键接口。
- 配置回滚
  1. 恢复上一个配置版本（JWT、支付、上游 API）。
  2. 清理受影响缓存键（若有错误缓存）。
- 数据处理
  - 支付订单与钱包流水不可逆，禁止回滚数据库写操作。
  - 使用补偿任务处理异常订单（重复到账/漏到账）。

## 4. 事故响应（P0）
- 触发条件：支付异常率 > 1%，或阅读服务不可用 > 5 分钟。
- 响应时限：5 分钟内拉群，15 分钟内给出止损方案。
- 复盘要求：24 小时内输出 RCA 与修复计划。
